# `.gplintrc`: reasons and sources

Why [`.gplintrc`](.gplintrc) lints `.feature` files the way it does, where its rules come from, and what was rejected. Read this only when changing or questioning a rule there. Writing a feature needs nothing from this file. [End-to-end testing](docs/engineering/testing/end-to-end-testing.md) says what to do when the lint fails.

Researched on 2026-11-22, and approved by the owner in the session that day for [PR #57](https://github.com/DetweilerRyan/split/pull/57). Why features are linted and formatted at all, and the precedents, are in [end-to-end testing's sidecar](docs/engineering/testing/end-to-end-testing.meta.md#linting-and-formatting-features).

## The linter

- **gplint 2.6.1** ([gplint](#gplint)). It is a maintained fork of gherkin-lint, with releases on 2026-10-31 and 2026-11-15. 2.6.1 is used because 2.6.2 was under two weeks old.
- **Not taken: `gherkin-lint-plus`,** the owner's `gol` repository's choice. It has one maintainer, was first published 2026-04-05, and has had no release since 2026-04-27. `gol` doesn't record why it chose it.
- **Not taken: `gherkin-lint`,** with no release since 2023-12.

## Rules ported from `gol`

- **Structure rules:** the rule set is `gol`'s `.gherkin-lintrc`, with two changes:
  - **`only-one-when` doesn't exist in gplint.** `max-keywords` with `when: 1` and `ignoreConjunctions: true` does the same. Without `ignoreConjunctions`, an `And` after a `When` counts as a second When.
  - **`no-dupe-scenario-names` is scoped `in-feature`,** so two features can each have a scenario of the same name.
- **The `max-scenarios-per-file` and `name-length` limits** are `gol`'s measured values, kept until a feature here shows they don't fit.
- **Layout rules are off:** indentation, trailing spaces, blank lines, end-of-file newline and `table-align`.
  - **Why:** the owner's `gol2` repository has only one tool decide layout, because "the two tools rewrite each other's output". Here that tool is `scripts/format-features.ts`.

## The vocabulary list

`no-restricted-patterns` fails a feature whose name, description or steps names how the app is built.

- **Its first run** caught `create_receipt_room` in a feature description, which was reworded in the same change.
- **The categories** come from web research on 2026-11-22. No source gives a word list. The sources name kinds of detail that don't belong in a scenario, and treat words like "click" as symptoms:
  - **Seb Rose's BRIEF:** "reveal intent, don't describe mechanics", keeping only the essential details ([BRIEF](#brief)).
  - **Practitioner guides list what leaks:** selectors and element ids, database tables and fields, endpoints and status codes, internal method names, URLs and browsers. They also flag "the language of clicking buttons and filling things in" ([helpmetest](#helpmetest), [andredesousa](#andredesousa), [CucumberStudio](#cucumberstudio), [Automation Panda](#automation-panda)).
  - **The patterns** group those kinds of detail into the six commented categories in `.gplintrc`. `should return` comes from `gol`'s list.
- **Snake_case, not camelCase.** gplint compiles every pattern ignoring case, so `\b\w+_\w+\b` catches any snake_case identifier, but camelCase can't be told apart from an ordinary word.
- **Examples cells aren't read** by the rule. `no-unused-variables` makes every Examples header appear in some step's `<placeholder>`, so between them the two rules cover the whole table.
- **Words left allowed:** `table` (where people eat), `link` (a room link is the product), `page`, `request` on its own, `phone`, and `MCP server` (the interface the assistant actor uses).
  - **Why:** Automation Panda accepts UI words when a feature is about the UI itself, and a pattern can only fail the lint, never warn. So a word that is only sometimes wrong stays off the list.
  - **Reopen when:** a feature is about the interface itself, such as keyboard navigation. Its UI words may then be what the scenario has to say.
- **Checked:**
  - None of the patterns matches the two current features.
  - A planted scenario got 13 findings. It named a URL, a snake_case table, the database, a field, a tap on a button, a wait in seconds, a GET request, an endpoint and a status code.
  - A planted scenario with two `When`s, a `Then` that should be `And`, `button` and `clicks` got six findings.

## oxCrap's features have their own config

[`scripts/oxcrap/features/.gplintrc`](scripts/oxcrap/features/.gplintrc) lints oxCrap's contract features. gplint 2.6.1 can't extend another config, so it copies every rule above `no-restricted-patterns` from this one. Only the vocabulary differs. Those features are about a developer tool, so they say function, complexity and config, and ban oxCrap's module and function names and how the test runs it instead. [Tooling testing's sidecar](docs/engineering/testing/tooling-testing.meta.md) says why.
