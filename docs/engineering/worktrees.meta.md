# Worktrees: reasons

Why [worktrees](worktrees.md) says what it does. Read this only when changing or questioning a rule there. Following the procedure needs nothing from this file.

- **Worktrees are the owner's choice.** On 2026-11-21 the owner asked agents to use a worktree per branch rather than switching branches in one checkout. Before that, the repository's procedures assumed a single checkout, and [post-merge cleanup](post-merge-cleanup.md) was adapted from the owner's market-research repository without its worktree steps. That earlier omission is not a reason to drop worktrees again.
- **Inside the checkout, not beside it.** The owner chose `.claude/worktrees/` over a sibling folder such as `../split-worktrees/<branch>` on 2026-11-21. It is where Claude Code's `EnterWorktree` tool puts worktrees, and it keeps them inside the folder the dev container mounts, so git and the checks work there. A sibling folder would need no config changes, but the dev container could not see it. Reopen this if the dev container comes to mount the repository's parent folder.
- **What keeps each check out of other worktrees.** Checked on 2026-11-21 with a worktree that had its own `node_modules`. From the main checkout, `vitest list` picked up the worktree's 60 test files and oxfmt checked 180 files instead of 91. `tsc --listFilesOnly` picked up none, because TypeScript's wildcards skip folders whose names start with a dot. oxlint and oxfmt follow `.gitignore`: a badly formatted file with an unused variable under `.claude/worktrees/` failed both checks without the `.gitignore` entry and passed with it. Vitest ignores `.gitignore`, so it has its own exclude. That exclude matches paths relative to the Vitest root, so a run inside a worktree still finds that worktree's own tests. If a tool is added to the definition of done, check whether it walks into `.claude/worktrees/`.
- **The dev container opens the main checkout.** `.devcontainer/devcontainer.json` mounts only the workspace folder and `/run/sandbox/source`. A worktree's `.git` file points at the main checkout's `.git/worktrees/<name>`, which is outside a worktree folder opened on its own, so git would fail there.
