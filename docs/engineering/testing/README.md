# Testing

How tests are written and checked in this repository, one kind of test, or check of the tests, per document. The [engineering index](../README.md) points here rather than to each document. Read this index before writing, changing, moving or reviewing a test, then each document whose "Read when" matches.

## Index

| Document                                                      | Read when                                                                                                                                                                                                                                                                                                                 |
| :------------------------------------------------------------ | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| [Testing conventions](testing-conventions.md)                 | Before writing, changing, moving or reviewing any test or the code that supports one, or when a test fails. Every kind of test follows it, as well as its own document below                                                                                                                                              |
| [Unit testing](unit-testing.md)                               | Before writing, changing, moving or reviewing a test in the `unit` project: a `<module>.test.ts(x)`, which runs in jsdom, an app `.property.test.ts` included; or before replacing an external dependency in any test                                                                                                     |
| [Component and hook testing](component-and-hook-testing.md)   | Before writing, changing, moving or reviewing a test of a React component or hook, a `<module>.browser.test.ts(x)`, or the React Compiler in `vitest.config.ts`                                                                                                                                                           |
| [End-to-end testing](end-to-end-testing.md)                   | Before writing, changing, moving or reviewing anything under `e2e/`, or `playwright.config.ts`: a feature, a step definition or the screenplay; or when `npm run test:e2e` fails                                                                                                                                          |
| [Tooling testing](tooling-testing.md)                         | Before writing, changing, moving or reviewing a test of the repository's own dev tools under `scripts/`, or the code that supports one, such as a tool's `features/`, or a test of root tooling config; or when `npm run test:tooling` fails                                                                              |

## Adding a document

1. Write it as `docs/engineering/testing/<kind>-testing.md`, one kind of test or check per file, and move that kind's rules out of [testing conventions](testing-conventions.md) in the same change, leaving a one-line pointer there.
   - **A document whose rules several kinds share** is named `<topic>-conventions.md`, as `testing-conventions.md` and `feature-testing-conventions.md` are. It doesn't name the kinds that follow it.
   - **A kind's document may point to a conventions document,** never to another kind's. A rule two kinds need goes in a conventions document both point to.
2. Add a row to the index above, with a "Read when" trigger specific enough that an agent knows whether it applies.
3. Put its reasons in a `<name>.meta.md` sidecar beside it, as [Reasons live in a `.meta.md` sidecar](../../prose/single-source-of-truth.md#reasons-live-in-a-metamd-sidecar) says, and move that kind's entries out of `testing-conventions.meta.md` with it. Don't give the sidecar an index row.
4. Keep this index to the table and these steps. A rule goes in a document, not here.
