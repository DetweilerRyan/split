# `.rumdl.toml`: reasons and sources

Why [`.rumdl.toml`](.rumdl.toml) checks Markdown links the way it does, where the choice came from, and what was rejected. Read this only when changing or questioning a setting there. Writing a document needs nothing from this file.

Researched on 2026-11-22 in [issue #61](https://github.com/DetweilerRyan/split/issues/61), and approved by the owner in the session that day: "i approve adding rumdl and the plan".

## What is checked

- **Internal links only:** MD057 (a relative link's file exists) and MD051 (a `#fragment` names a heading or anchor in the same file or the linked file).
  - **Why:** the docs are mostly linked to each other. On 2026-11-22 the 32 tracked `.md` files held 142 relative links and 84 links with a `#fragment`. They break when a doc or heading moves, and they can be checked offline.
- **HTML anchors count.** The sidecars' source lists use `<a id="…"></a>`, and rumdl resolves links to them.
- **Checked:** with these two rules, rumdl found nothing on the repository. A planted line with a link to a missing file, a bad anchor in another file and a bad anchor in the same file failed `npm run lint` with three findings, each naming its line. A good cross-file anchor beside them passed.
- **No cache.** The check takes about 10 ms, so `cache = false` saves adding `.rumdl_cache` to `.gitignore`.
- **No `flavor`.** rumdl's schema maps `github` and `commonmark` to its default, `standard`, and reported a `gfm` setting as `standard`, so the setting had no visible effect.

## The tool

- **rumdl 0.3.2** ([rumdl](#rumdl)): MIT, 30 contributors, releases about weekly, not yet 1.0, one npm maintainer. 0.3.2 (2026-10-28) was the newest release at least two weeks old.
  - **What it adds:** a launcher package and a per-platform binary, as oxlint and oxfmt ship, with no other dependencies. `npm audit` found nothing.
  - **Precedent:** the owner's market-research repository runs `rumdl check .` in its definition of done for structure and relative links.
- **Not taken: markdownlint-cli2 0.24.x with markdownlint-rule-relative-links 5.1.4** ([markdownlint-cli2](#markdownlint-cli2)). It caught the same planted faults, but installs 92 packages, needs the plugin for cross-file anchors, and 0.24.0, the newest release two weeks old on 2026-11-22, carries a high `re2js` advisory. It is the fallback if rumdl stops fitting: the swap changes this config file and the `lint` script.
- **Not taken: remark-cli 12.0.1 with remark-validate-links 13.1.0.** It reported 26 false positives on the repository, because it doesn't resolve `<a id>` anchors, and its last releases (2024-04-30 and 2025-02-21) fall outside the 12-month rule in [dependencies](docs/engineering/dependencies.md#evaluating).
- **Not taken: writing it.** Matching GitHub's heading anchors, HTML anchors and reference links is a general problem a tool already solves.

## What is not checked

- **rumdl's other rules are off.** With its defaults, the repository had 469 findings on 2026-11-22: 444 for line length (MD013) and 23 for inline HTML (MD033, the sidecars' anchors). MD018 also flags a paragraph in `docs/engineering/ci.meta.md` that opens with `#52`, which CommonMark doesn't treat as a heading.
  - **Reopen when:** a structure rule would catch a mistake review keeps missing. Check first that it agrees with oxfmt.
- **`rumdl fmt` isn't used; oxfmt formats Markdown.** On a copy of the repository, `rumdl fmt` rewrote that `#52` paragraph as the heading `## 52 proposed…`, dropping its full stop, and changed two `##` headings to `###`. oxfmt then rejected the file. On a messy sample, rumdl left emphasis markers, `+` list markers, an unaligned table and an unformatted JSON block as they were, all of which oxfmt fixes.
- **External URLs aren't checked.** They need network access the [sandbox kit's network policy](.sbx-kits/splitsmart/splitsmart.yaml) mostly blocks, and remote sites make a check flaky.
  - **Reopen when:** dead external links become a problem. lychee in a scheduled CI job, outside the definition of done, is the candidate; it is a binary from GitHub releases, and the npm package named `lychee` is unrelated.
